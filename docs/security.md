# 입력 검증

Lambda 이벤트는 호출자가 제공하는 입력입니다. 처리 순서는 타입 검증, 전체 개수와 수집 개수의 범위 검증, 해금 기준 검증, 계산입니다. 타입 검증은 불리언과 숫자 문자열을 거부합니다. 입력 오류는 고정된 메시지로 응답하며 원본 입력값을 메시지에 포함하지 않습니다.

테스트는 불리언, 범위 경계, 여러 조건이 동시에 실패할 때의 검증 순서와 기존 응답 형식을 확인합니다.

전체 개수의 상한은 `2**53 - 1`입니다. 이 범위의 정수는 JavaScript처럼 JSON 숫자를 IEEE 754 배정밀도로 처리하는 클라이언트에서도 정밀도를 유지합니다. 전체 개수와 수집 개수의 범위를 나눗셈 전에 검사합니다.

핸들러는 이미 역직렬화된 이벤트를 받으므로 요청 본문의 크기와 JSON 파싱 비용은 호출 경계에서 관리해야 합니다. 유효한 범위의 값도 실제 수집 기록과 일치하는지는 호출 서비스가 확인해야 합니다.

## 로그 보안 정책

- 완료 로그는 고정 메시지와 네 개의 구조화 필드만 애플리케이션에서 제공합니다. `request_id`는 Lambda 컨텍스트의 `aws_request_id`에서 가져오며 문자열 ID가 없으면 `null`입니다. `duration_ms`는 핸들러 시작부터 완료 로그 직전까지의 경과 시간입니다.
- 성공은 `INFO` 및 `outcome=success`로 기록하고 `error_code`는 `null`로 둡니다. 검증 실패는 `WARNING` 및 `outcome=validation_failed`와 함께 고정 코드 `INVALID_INPUT_TYPE`, `INVALID_COLLECTION_DATA`, `INVALID_UNLOCK_THRESHOLD` 중 하나로 기록합니다. 분류되지 않은 검증 오류에는 `VALIDATION_FAILED`를 사용합니다.
- 이벤트와 응답 원문, 사용자 식별 정보, 인증 헤더 및 토큰, AWS 자격 증명은 기록 대상에서 제외합니다. 로깅 중 발생한 예외도 기존 응답에 영향을 주지 않도록 로깅 경계에서 처리합니다.
- 구조화 필드는 표준 `logging`의 `extra`로 전달합니다. JSON 직렬화는 Lambda의 로그 설정에서 처리합니다.

### CI에서의 Bandit 판정

CI는 운영 코드 `src`에 대해 모든 심각도의 결과를 출력한 뒤, 중간·높음 경고가 있으면 실패합니다. 로컬 전체 검사에서 나왔던 테스트 코드 24건은 위 표에 별도로 기록했습니다. 운영 코드의 낮음 등급 B110은 CI 출력에서 확인할 수 있습니다. 로깅 예외를 흡수하는 이유는 기존 Lambda 응답을 유지하기 위해서이며, 로깅 시스템에 장애가 발생하면 완료 로그가 유실될 수 있습니다.
